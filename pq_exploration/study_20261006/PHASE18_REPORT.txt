Qwen3-0.6B — Round18 overfitting and MMLU audit

All model/checkpoint choices were frozen on the fresh monitor before MMLU TEST. Training and initial evaluation used scai4:2. Large final quantized evaluators were split across scai4:2 and5 after one process occupied32GiB including allocator cache; maximum concurrency was two GPUs. The smaller FP16 controls were consolidated serially on GPU2. See MMLU18_SCHEDULING_UPDATE.json.
Do not attribute NLL-adapted versus unadapted FP16 gains to quantization. Matched controls tune original FP16 weights through the same number of bounded group gains, then merge them offline.
MMLU: 57 subjects, all14042 test questions,5-shot first5 dev examples,raw A/B/C/D continuation likelihood,no chat template,no generated reasoning,micro accuracy. This is not Qwen advertised thinking-mode evaluation.
PPL: WikiText2 raw,2048-token nonoverlapping contexts,298862 scored TEST tokens. This TEST has been reused in prior rounds. New monitor and final audit each32x2048 use token-disjoint historical TRAIN windows with2048-token buffers from fitting windows; they are not document-disjoint and do not establish pretraining decontamination.
Training: same128x512 windows and256-update maximum,Adam lr0.01,4-window accumulation,2% bounds from immutable pre-adaptation scales. Select from0/64/128/256 separately for every trajectory using fresh monitor NLL. Teacher KL strength1,temperature1 fixed before results. MMLU scores did not select checkpoints. All ten adapted trajectories selected update256; early stopping did not trigger.

Counts cover196 decoder linears per generated token. Embeddings,LM head,QK/AV,norms and nonlinearities excluded equally. Dense counts/memory are historical rounded baselines. Quantized rows include resident compressed weights,tables,scales and peak linear scratch;287k reciprocals/token are separate. No change in deployed storage or arithmetic from scale-only training.
PQ: W8A9,g128,K480,12bit indices,INT32 tables. RQ: W7A9,g64,27x32 residual centers fused offline into630 centers,13bit indices,INT16 tables. IB: W7A9,g64,K858,lambda0.8,covariance-compensated assignments,13bit indices,INT16 tables. FP16 scales,FP32 accumulation.
E_ref=(3.8*lookup+0.4*add+1.3*mul)/1e9. Uniform7nm logical reference proxy,NOT measured FPGA energy.286916 reciprocals cost an optional0.000372991mJ/token at the multiplication coefficient. Index/scale reads and bit/address logic are separate from dot-table lookups. LUT-LLM is a resource baseline,not a reproduction of paper QAT accuracy.
Quantized full PPL/MMLU use the independent deployed-arithmetic reference. All196 packed-layer outputs and actual8x256 packed short PPL were verified before each quantized final PPL. PPL uses the original frozen evaluator with TF32 enabled only around exactly representable integer group dots and FP32 sums below2**24. The separate amended MMLU backend fuses those integer group dots (exact FP16 integer operands,FP32 accumulation) with the original FP32 scale/reduction tree; compiler FP fusion is disabled. All196 layer outputs and24 validation score fixtures per model must be exactly equal to the original FP32 reference. Full original FP16 MMLU is reused; completed original partial PQ/RQ subjects must match the fused backend score-for-score. Original evaluator files and every selected model remain unchanged,with hashes recorded in MMLU18_BACKEND_AMENDMENT.json and overfit18_mmlu_index.json. Other matmuls and all training retain their original precision.
MMLU uses full context,at most8 questions/4096 padded tokens per batch,same deterministic batching for every model,no shared-prefix reuse,config.use_cache=True to match HFLM,FP32 log-softmax; last-position LM head scoring is checked against installed HFLM with matched batches on24 MMLU validation fixtures per model. FP16 controls use the same scorer with zero fused quantized modules and retain native dense FP16 linears. No test question was truncated. Rejected prefix-cache,use_cache=False and mismatched-batch checks are retained in logs.

Limitations: one training seed,one fixed KL strength; selected checkpoints share a monitor; monitor/audit are same-corpus,token-disjoint rather than document-disjoint. A higher MMLU result on this fixed benchmark is evidence of retention,not proof that all overfitting is eliminated. Future tuning after viewing these MMLU scores needs a new final audit.
